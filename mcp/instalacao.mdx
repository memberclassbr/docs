## 1. Obter o servidor

<Warning>
  O binário ainda **não é distribuído**: hoje ele é compilado a partir do
  repositório do backend. Enquanto a publicação não sai, peça o binário ao time
  da Yeon ou compile com Go 1.25:

  ```bash
  make build-mcp        # gera bin/yeon-mcp
  ```
</Warning>

## 2. Gerar a chave

No [Painel](https://app.yeon.com.br), nas configurações do projeto, gere um token de API com as permissões que a sua integração precisa.

Escolha as permissões com cuidado: **elas são definidas na criação e não mudam depois**. Precisar de mais é gerar outra chave e trocar a configuração. Veja [Permissões da chave](/api/permissoes).

<Note>
  Quer um agente que só consulta? Gere uma chave só com as permissões de leitura
  (`catalog:read`, `billing:read`, …). É mais forte do que qualquer configuração
  do servidor, porque vale para qualquer cliente que use a chave.
</Note>

## 3. Configurar

Tudo vem do ambiente do processo.

| variável | obrigatória | o que é |
| --- | --- | --- |
| `YEON_API_URL` | sim | `https://api.yeon.com.br` |
| `YEON_API_TOKEN` | sim | o token gerado no Painel |
| `YEON_MCP_GROUPS` | **sim** | os [grupos](/mcp/grupos) que você usa, separados por vírgula |
| `YEON_MCP_READONLY` | não | `true` remove toda ferramenta que modifica dados |
| `YEON_MCP_TIMEOUT_SECONDS` | não | timeout de cada chamada (padrão 30) |

`YEON_MCP_GROUPS` não tem valor padrão de propósito — [entenda por quê](/mcp/grupos).

## 4. Registrar no Claude Code

```bash
claude mcp add yeon \
  --scope local \
  --env YEON_API_URL=https://api.yeon.com.br \
  --env YEON_API_TOKEN="$YEON_API_TOKEN" \
  --env YEON_MCP_GROUPS=catalog,sales \
  -- /caminho/absoluto/para/yeon-mcp
```

<Warning>
  Nunca escreva o token direto num arquivo versionado. Use variável de ambiente,
  como acima. Se um token vazar, revogue-o no Painel e gere outro.
</Warning>

### Escopo da configuração

O escopo controla **onde a configuração fica disponível no seu cliente** — não qual projeto da Yeon o agente alcança. Esse continua vindo da chave, em qualquer diretório.

| escopo | onde vale |
| --- | --- |
| `local` | só para você, só neste projeto (padrão) |
| `project` | versionado em `.mcp.json`, compartilhado com o time — **não** ponha chave aqui |
| `user` | você, em qualquer projeto |

## 5. Validar

```bash
claude mcp list          # deve dizer "✔ Connected"
claude mcp get yeon      # confere transporte, comando e ambiente
```

Dentro do Claude Code, `/mcp` lista as ferramentas — é aí que você confere que **só os grupos que você ligou apareceram**.

Depois peça algo simples, como *"lista os produtos do meu projeto"*. Se voltar a lista, está de pé.

## Diagnosticar

| sintoma | causa provável |
| --- | --- |
| `Failed to connect` | caminho do binário errado, ou configuração inválida — rode o binário no terminal e leia a saída |
| `YEON_MCP_GROUPS é obrigatório` | falta escolher os grupos |
| tudo responde `API_TOKEN_INVALID` | chave errada, revogada, ou apontando para outro ambiente |
| tudo responde `API_TOKEN_SCOPE_MISSING` | a chave não tem a permissão — gere outra, não adianta repetir |
| uma ferramenta sumiu | o grupo saiu de `YEON_MCP_GROUPS`, ou `YEON_MCP_READONLY` foi ligado |
| `429` | teto de requisições da chave; o erro diz quantos segundos esperar |

Toda chamada leva um identificador de correlação, e o erro o devolve — é ele que o suporte usa para achar a requisição.

## Trocar a chave ou remover

Trocar a chave é editar a configuração e reconectar; não há como trocá-la em tempo de execução.

```bash
claude mcp remove yeon --scope local
```
