## Permissões

O servidor não tem permissões próprias: ele repassa as chamadas à API com a sua credencial, e a API decide.

As permissões são as que você aprovou na tela de autorização — ou, se você conectou com uma chave de API, as dela. Sem `billing:refund`, por exemplo, nenhum caminho devolve dinheiro.

**Reembolso, saque e gestão de equipe não entram por padrão.** Um aplicativo que precise deles tem de pedi-los explicitamente, e você vê o pedido na tela antes de autorizar.

Quando falta permissão, a resposta é:

```
403 API_TOKEN_SCOPE_MISSING
```

Permissões não mudam depois de autorizadas. Para mudar, desconecte em **Aplicativos** e autorize de novo.

A credencial é conferida a cada chamada. Desconectar no Painel corta o acesso na chamada seguinte, sem precisar mexer no agente.

## Modo leitura

```text
https://api.yeon.com.br/mcp?readonly=true
```

Carrega apenas as 41 ferramentas de consulta. As 42 que modificam dados não são registradas — não aparecem na lista nem podem ser chamadas.

## Projeto

Nenhuma ferramenta aceita `project_id`, `account_id` ou `seller_id`. O projeto é sempre o que você escolheu ao autorizar.

Enviar um projeto diferente onde a API aceitaria o campo retorna:

```
400 DESTINATION_PROJECT_MISMATCH
```

## Repetir uma operação

17 operações — reembolso, saque, convite, adesão, aceite — aceitam `idempotency_key`. O servidor gera uma quando você não informa.

Depois de um erro de rede, repita **com a mesma chave** para não duplicar o efeito. A chave vem na mensagem de erro:

```
Para repetir com segurança, chame de novo com idempotency_key="8f3a1c62-…"
e os MESMOS argumentos: a API devolve o resultado da primeira tentativa em
vez de executar outra.
```

O servidor não repete operações automaticamente.

## Dados sensíveis

- número de cartão, CVV e senha não são aceitos como argumento;
- tokens de gateway e a sua credencial não aparecem em respostas nem em erros;
- arquivos são enviados como URL já hospedada; o servidor não lê arquivos do seu disco.

## Conteúdo de terceiros

Nomes de produto, mensagens de clientes e corpos de webhook são escritos por outras pessoas e voltam como dados da API.

Revise operações que movem dinheiro ou concedem acesso antes de aprovar. Para um agente que só consulta, conecte com `readonly=true`.
