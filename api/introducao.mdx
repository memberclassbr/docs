A API pública da Yeon permite que sellers consultem os dados dos seus projetos de forma programática. Todas as requisições usam HTTPS e retornam JSON.

```text
https://api.yeon.com.br
```

## Autenticação

Cada requisição precisa de um token de API enviado no header `Authorization`, no formato Bearer:

```bash
curl https://api.yeon.com.br/api/public/v1/products \
  -H "Authorization: Bearer <token>"
```

O token é gerado no [Painel](https://app.yeon.com.br), nas configurações do seu projeto, e é **escopado a um único projeto**: ele só acessa os dados do projeto em que foi criado.

<Warning>
  Trate o token como uma senha. Não o exponha em código de frontend, repositórios públicos ou logs. Se um token vazar, revogue-o no Painel e gere um novo.
</Warning>

Requisições sem token, com token inválido ou revogado recebem `401 Unauthorized`.

## Rate limit

O limite é de **1 requisição por segundo por IP**. Acima disso, a API responde `429 Too Many Requests`. Ao receber `429`, aguarde um instante e tente novamente.

## Envelope de resposta

Toda resposta segue o mesmo envelope:

```json
{
  "success": true,
  "data": { ... }
}
```

Em caso de erro, `success` é `false` e `error` descreve o problema:

```json
{
  "success": false,
  "error": "invalid token"
}
```

## Paginação

Endpoints de listagem usam paginação por `limit` e `offset`:

<ParamField query="limit" type="integer" default="20">
  Itens por página. Máximo de `100`.
</ParamField>

<ParamField query="offset" type="integer" default="0">
  Deslocamento a partir do início da lista.
</ParamField>

A resposta inclui um objeto `pagination`:

```json
{
  "pagination": {
    "limit": 20,
    "offset": 0,
    "has_more": true,
    "next_offset": 20
  }
}
```

Enquanto `has_more` for `true`, use `next_offset` como `offset` da próxima requisição. Quando não há mais páginas, `next_offset` é `null`.
