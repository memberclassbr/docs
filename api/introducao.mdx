A API pública da Yeon permite que sellers consultem os dados dos seus projetos de forma programática. Todas as requisições usam HTTPS e retornam JSON.

```text
https://api.yeon.com.br
```

## Autenticação

Cada requisição precisa de um token de API enviado no header `Authorization`, no formato Bearer:

```bash
curl https://api.yeon.com.br/api/public/v1/products \
  -H "Authorization: Bearer <token>"
```

O token é gerado no [Painel](https://app.yeon.com.br), nas configurações do seu projeto, e é **escopado a um único projeto**: ele só acessa os dados do projeto em que foi criado.

<Warning>
  Trate o token como uma senha. Não o exponha em código de frontend, repositórios públicos ou logs. Se um token vazar, revogue-o no Painel e gere um novo.
</Warning>

Requisições sem token, com token inválido ou revogado recebem `401 Unauthorized`.

## Permissões

Além de pertencer a um único projeto, cada token carrega **permissões** escolhidas na criação: uma operação só responde se a chave puder executá-la. Sem a permissão, a resposta é `403` com `error_code` `API_TOKEN_SCOPE_MISSING`.

Veja [Permissões da chave](/api/permissoes) para a lista e como elas se contêm.

## Rate limit

Os limites são **por chave**, com contadores separados para leitura e escrita. Ao exceder, a API responde `429 Too Many Requests` com `error_code` `API_TOKEN_RATE_LIMITED`; o cabeçalho `Retry-After` diz em quantos segundos tentar de novo.

## Envelope de resposta

Toda resposta segue o mesmo envelope:

```json
{
  "success": true,
  "data": { ... }
}
```

Em caso de erro, `success` é `false` e `error` descreve o problema:

```json
{
  "success": false,
  "error": "invalid token"
}
```

## Paginação

Endpoints de listagem usam paginação por `limit` e `offset`:

<ParamField query="limit" type="integer" default="20">
  Itens por página. Máximo de `100`.
</ParamField>

<ParamField query="offset" type="integer" default="0">
  Deslocamento a partir do início da lista.
</ParamField>

A resposta inclui um objeto `pagination`:

```json
{
  "pagination": {
    "limit": 20,
    "offset": 0,
    "has_more": true,
    "next_offset": 20
  }
}
```

Enquanto `has_more` for `true`, use `next_offset` como `offset` da próxima requisição. Quando não há mais páginas, `next_offset` é `null`.

## Dinheiro, sempre em centavos

Todo valor monetário é um inteiro em **centavos** — `9900` é R$ 99,00. Não há ponto flutuante em lugar nenhum da API.

## Oferta, pedido, transação e cobrança

Quatro palavras que não são sinônimos:

<ParamField path="Oferta" type="unidade de venda">
  É o que o comprador compra: preço, moeda, parcelamento, cadência e meios de pagamento vivem nela, não no produto. É a oferta que carrega o link de checkout (`public_id`).
</ParamField>

<ParamField path="Pedido" type="agregação do checkout">
  Uma ida ao checkout. Pode conter mais de um produto (o principal e os order bumps) e, no pagamento dividido, mais de uma cobrança.
</ParamField>

<ParamField path="Transação" type="a venda de um produto">
  Uma linha do pedido. Um pedido com um bump tem duas transações.
</ParamField>

<ParamField path="Cobrança" type="grão do gateway">
  O que foi cobrado de uma vez: um QR de Pix, uma captura de cartão. É onde o dinheiro se move.
</ParamField>
